1️⃣ جدول أساسي لتصنيفات المراحل

stage_types
يحمل جميع أنواع المراحل الممكنة اللي عندنا في المصنع.

العمود	النوع	الشرح
id	uuid	رقم المرحلة
category	text	فئة المرحلة (تصميم / طباعة / تجهيز / بعد الطباعة / تغليف / تسليم...)
name	text	اسم المرحلة (سلوفان مط، يوفي، بصمة...)
is_optional	bool	هل المرحلة اختيارية
allow_multiple	bool	هل يمكن دمجها مع غيرها
domain	text	المجال اللي تخصه (علب / كرتون / الكل)

📌 مثال بيانات:

category	name	is_optional	allow_multiple	domain
تصميم	تصميم داخلي	true	false	boxes
تصميم	تصميم عميل	true	false	boxes
تجهيز	تجهيز زنكات	true	false	boxes
طباعة	طباعة أوفست	false	false	boxes
بعد الطباعة	سلوفان مط	true	true	boxes
بعد الطباعة	سلوفان لامع	true	true	boxes
بعد الطباعة	يوفي	true	true	boxes
بعد الطباعة	سبوت يوفي	true	true	boxes
بعد الطباعة	بصمة	true	true	boxes
بعد الطباعة	كوفراج	true	true	boxes
تغليف	تجميع وتلزيق	false	false	boxes
تسليم	تسليم نهائي	false	false	boxes
2️⃣ جدول مراحل العملية الفعلية

operation_stages

العمود	النوع	الشرح
id	uuid	معرف المرحلة الفعلية
operation_id	uuid	العملية المرتبطة
stage_type_id	uuid	نوع المرحلة (من stage_types)
status	text	pending / in-progress / done
started_at	timestamp	وقت البدء
finished_at	timestamp	وقت الانتهاء
assigned_to	uuid	المسؤول
notes	text	ملاحظات
3️⃣ كيف بيشتغل النظام فعليًا

لما تنشئ عملية جديدة، التطبيق بيجيب قائمة المراحل المقترحة من stage_types بناءً على المجال.

المستخدم (أو المشرف) يختار المراحل اللي مطلوبة فعلًا في العملية الحالية.

لو التصميم مع العميل → يحذف مرحلة التصميم.

لو هنعمل سلوفان + سبوت يوفي → يضيف المرحلتين.

بعد الحفظ، تتنسخ الاختيارات دي في operation_stages.

سير العمل بعد كده يتابع على operation_stages بس.

ممكن تتابع كل مرحلة بحالتها وزمنها وشخصها.

🧩 مثال عملي (علبة معينة)
المرحلة	الحالة	المسؤول
تصميم عميل	Done	---
تجهيز زنكات	Skipped	---
طباعة أوفست	Done	سامح
سلوفان مط	In Progress	حسين
سبوت يوفي	Pending	أحمد
تجميع وتلزيق	Pending	محمود
تسليم نهائي	Pending	مخزن
✅ المزايا
نقطة	الفائدة
